# ชุดประเมินผล (Evaluation harness)

ใช้ในขั้นประเมินผล (Phase 4) ของวิทยานิพนธ์ เพื่อวัดว่าระบบตัดสินใบเสร็จตรงกับเจ้าหน้าที่การเงินแค่ไหน
และเทียบกับการให้ AI ตัดสินเองล้วน

## วิธีรัน

```
node research/eval/run-eval.js research/eval/cases.example.csv
```

- `--baseline`: ให้ AI ตัดสินเองทุกเคสด้วย ถ้าใช้ API แบบเสียเงินจะมีค่าใช้จ่ายทุกเคส
- `--show-prompt <case_id>`: แสดงข้อความที่จะส่งให้ AI โดยไม่เรียก AI จริง (ใช้ใส่ภาคผนวกได้)

ผลลัพธ์จะอยู่ที่ `research/eval/output/` เป็นไฟล์ `.md` (ตาราง) กับ `.json` (ข้อมูลดิบทุกเคส)

`cases.example.csv` เป็น**เคสสมมติ**ไว้ทดสอบโค้ดเท่านั้น ห้ามรายงานเป็นผลวิจัย

## ข้อมูลจริง

1. ให้วางไฟล์ไว้ใน `research/eval/data/` โฟลเดอร์นี้ gitignored และห้าม commit
2. ใส่เฉพาะข้อมูลที่ใช้ตัดสิน ไม่ต้องมีชื่อคน เลขบัตร หรือชื่อร้าน
3. ต้องได้รับอนุมัติจริยธรรมการวิจัย (EC) ก่อนเก็บข้อมูล

## คอลัมน์ของไฟล์เคส

ใช้ Excel หรือ Google Sheets แล้ว export เป็น CSV (UTF-8)

| คอลัมน์ | ความหมาย |
|---|---|
| `case_id` | รหัสเคส ห้ามซ้ำ |
| `category` | หมวดค่าใช้จ่าย ต้องสะกดตรงกับหมวดในระบบ (ดูรายการใน `app/js/data.js` → `categories`) |
| `amount` | ยอดเงินในใบเสร็จ |
| `in_estimate` | `yes` = อยู่ในประมาณการ, `no` = ไม่อยู่ในประมาณการ, ว่าง = โครงการไม่มีประมาณการ |
| `line_name` | ชื่อรายการในประมาณการ (ไม่บังคับ) |
| `line_total` | ยอดที่ตั้งไว้ในประมาณการของรายการนั้น |
| `line_quantity` | จำนวนหน่วยจากช่องตัวคูณ เช่น 100 ชม., 1200 กม., 40 คน×มื้อ (ไม่มีให้เว้นว่าง) |
| `spent_before` | ยอดที่เบิกจากรายการนี้ไปแล้วก่อนใบนี้ |
| `documents` | รหัสเอกสารที่แนบ คั่นด้วย `;` เช่น `tax-invoice-full;inspection-photos` ถ้าไม่ได้แนบอะไรเลยให้ใส่ `none` |
| `attestations` | สิ่งที่ยืนยันบนเอกสาร: `paid-stamp` (ตราจ่ายแล้ว), `inspection-stamp` (ตราตรวจรับพัสดุ) |
| `summary_amount` | ยอดที่นักวิจัยลงไว้ในใบสรุปรายรับ-จ่าย (ไม่บังคับ; ว่าง = ไม่เทียบ) |
| `finance_verdict` | ผลที่การเงินตัดสินจริง: `ผ่าน` / `ต้องแก้ไข` / `ต้องชี้แจง/ขออนุมัติ` / `ไม่เข้าเงื่อนไข` |
| `finance_note` | เหตุผลของการเงิน ใช้วิเคราะห์เคสที่ไม่ตรงกัน |

ถ้าเว้น `documents` กับ `attestations` ว่างทั้งคู่ ระบบจะไม่ตรวจเอกสารของเคสนั้น

รหัสเอกสารทั้งหมดอยู่ใน `app/js/data.js` → `documentTypes`

## ตัวชี้วัดในรายงาน

| ตัวชี้วัด | ความหมาย |
|---|---|
| accuracy | สัดส่วนเคสที่ผลตรงกับการเงิน |
| Cohen's kappa | ความตรงกันที่หักส่วนที่บังเอิญตรงออกแล้ว (1 = ตรงทั้งหมด, 0 = ไม่ดีกว่าสุ่ม) |
| macro F1 | ค่าเฉลี่ย F1 ของทั้ง 4 ผลตัดสิน ไม่ให้ผล "ผ่าน" ที่มีจำนวนมากกลบผลอื่น |
| missed | ใบที่การเงินบอกว่ามีปัญหา แต่ระบบปล่อยผ่าน **เป็นความผิดพลาดที่ร้ายแรงที่สุด** |
| false alarm | ใบที่ผ่าน แต่ระบบทักผิด ทำให้นักวิจัยเสียเวลา |
| confusion matrix | แต่ละผลถูกตัดสินเป็นอะไรบ้าง |

## ตั้งค่า AI สำหรับ baseline

สร้างไฟล์ `research/eval/ai-config.local.json` (gitignored) ใช้รูปแบบเดียวกับ `window.AI_CONFIG` ของเว็บ
(ดู `app/js/ai-config.example.js`)

ตัวอย่างใช้ Ollama ในเครื่อง ฟรีและใบเสร็จไม่ออกจากเครื่อง:

```json
{ "provider": "ollama", "model": "gemma3:4b" }
```

ใช้ OpenRouter:

```json
{ "provider": "openrouter", "apiKey": "sk-or-v1-...", "model": "google/gemini-2.5-flash-lite" }
```

**ข้อควรระวัง:** ถ้าจะรายงานผลเทียบกัน ต้องใช้โมเดลเดียวกับที่เว็บใช้อธิบายผล
