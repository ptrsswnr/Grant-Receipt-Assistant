> แปลงจาก [[user-journey#Journey 1: นักวิจัยอัปโหลดใบเสร็จและตรวจสอบผลจนผ่านเกณฑ์|Journey 1]]

## 0. สถานะเอกสารและสถานะการสร้าง

- **เขียนใหม่ทั้งไฟล์ 2026-11-17** ให้ตรงกับ [[api-spec]] (OP-01–OP-39) / [[db-spec]] (E-01–E-24) ที่ sync วันนี้ ของเดิมอ้าง Backend Service,
  ใบเสร็จสถานะ "รอ OCR" ที่บันทึกถาวร และ OP-03 ซึ่งไม่มีแล้ว
- **สาระสำคัญที่เปลี่ยน:** ใบเสร็จ (`Receipt`) และไฟล์อ้างอิง (`ReceiptFile`) **ถูกสร้างตอนส่งตรวจ** ไม่ใช่ตอนเลือกไฟล์ การอ่านด้วย AI/OCR (OP-02)
  เสนอค่าบนหน้าจอเท่านั้น ไม่บันทึกข้อมูล

| ส่วนของฟีเจอร์ | Operation | สถานะ |
|---|---|---|
| ตรวจ/ให้ความยินยอมก่อนอัปโหลดครั้งแรก | OP-13, OP-14 | สร้างบางส่วน (ยินยอมแบบเบา) |
| เลือกโครงการที่จะผูกใบเสร็จ | OP-18 | สร้างแล้ว |
| เชื่อมต่อที่เก็บไฟล์ภายนอกของผู้ใช้ | OP-29 | สร้างแล้ว |
| อ่านใบเสร็จด้วย AI/OCR เพื่อเสนอค่า | OP-02 | สร้างแล้ว (รายละเอียดที่ [[02-design/02-technical/detailed-design/ai-ocr-receipt-reading\|ai-ocr-receipt-reading]]) |
| อัปโหลดไฟล์ไปที่เก็บไฟล์ภายนอกและบันทึกข้อมูลอ้างอิง | OP-38 | สร้างแล้ว |
| ตรวจชุดไฟล์ (ชนิด/ขนาด 5 MB/จำนวน 1–5 ไฟล์/ไฟล์เสียหาย) | OP-01 | **Backlog** (FR-19/FR-22 ยังไม่ได้บังคับในระบบที่สร้าง) |

## 1. ภาพรวม

ลำดับ: ผ่านเงื่อนไขความยินยอม → เลือกโครงการ → แนบไฟล์ (เตือน "ครั้งละ 1 รายการ") → (ถ้าแนบไฟล์) เชื่อมต่อที่เก็บไฟล์ภายนอก → อ่านด้วย AI/OCR
เพื่อเสนอค่า → ไปขั้นตรวจทาน ([[02-design/02-technical/detailed-design/review-edit-ocr-data|review-edit-ocr-data]]) → ส่งตรวจ
([[02-design/02-technical/detailed-design/rule-engine-verification|rule-engine-verification]]) แล้วจึงอัปโหลดไฟล์ (OP-38)
Component: Client, Receipt Reader, Primary Data Store, User-owned External File Store

## 2. Sequence Diagram

```mermaid
sequenceDiagram
    actor R as นักวิจัย/เจ้าของโครงการ
    participant C as Client
    participant RR as Receipt Reader
    participant DS as Primary Data Store
    participant FS as External File Store

    R->>C: เปิดหน้าอัปโหลดใบเสร็จ
    C->>DS: OP-13 ดูสถานะยินยอม
    DS-->>C: privacyConsentAcceptedAt มีหรือไม่มี
    alt ยังไม่เคยยินยอม
        C-->>R: แจ้งว่า Admin อ่านข้อมูลใบเสร็จได้แบบอ่านอย่างเดียว
        R->>C: ติ๊กยอมรับ
        C->>DS: OP-14 ให้ความยินยอม (ตั้ง privacyConsentAcceptedAt)
    end
    C->>DS: OP-18 ดูรายการโครงการของตนเอง
    DS-->>C: รายการ Project (อาจว่าง)
    alt ยังไม่มีโครงการ
        C-->>R: พาไปสร้างโครงการ (ดู project-setup)
    else มีโครงการ
        R->>C: เลือกโครงการ
        C-->>R: เตือน อัปโหลดครั้งละ 1 รายการ รายการเดียวกันได้ไม่เกิน 5 ไฟล์
        R->>C: เลือกไฟล์ใบเสร็จ
        opt OP-01 ตรวจชุดไฟล์ที่ Client (Backlog)
            C-->>R: ไม่ผ่าน แจ้งเหตุผลภาษาไทยต่อไฟล์ ปฏิเสธทั้งชุด
        end
        opt แนบไฟล์จริง
            R->>C: กดเชื่อมต่อที่เก็บไฟล์
            C->>FS: OP-29 ขออนุญาตแบบขอบเขตแคบ
            FS-->>C: การอนุญาต (เก็บในหน่วยความจำ หมดอายุภายในไม่นาน)
        end
        C->>RR: OP-02 อ่านใบเสร็จเพื่อเสนอค่า
        RR-->>C: ค่าที่เสนอ + เส้นทางที่ใช้จริง
        C-->>R: แสดงฟอร์มตรวจทาน (ไปต่อที่ review-edit-ocr-data)
    end
    Note over C,FS: เมื่อผู้ใช้ส่งตรวจ OP-04 สร้าง Receipt ก่อน แล้ว OP-38 อัปโหลดไฟล์ และบันทึก ReceiptFile
    C->>FS: OP-38 อัปโหลดไฟล์เข้าโฟลเดอร์ตามรหัสใบเสร็จ
    C->>DS: OP-38 บันทึก ReceiptFile ต่อไฟล์
```

## 5. Edge Case และวิธีจัดการ

| # | Edge Case | วิธีจัดการ | อ้างอิง |
|---|---|---|---|
| 1 | ยังไม่ยินยอม | บล็อกพร้อมคำเตือนจนกว่าจะติ๊ก (ไม่ใช่ error) | OP-14, FR-14 |
| 2 | ยังไม่มีโครงการ | OP-18 คืนรายการว่าง Client พาไปสร้างโครงการก่อน | OP-18, [[02-design/02-technical/detailed-design/project-setup\|project-setup]] |
| 3 | ไฟล์ผิดชนิด เสียหาย เกิน 5 MB หรือเกิน 5 ไฟล์ | ปฏิเสธทั้งชุดพร้อมเหตุผลภาษาไทย — **ยังเป็น Backlog** ระบบที่สร้างแล้วไม่บังคับครบ และการตรวจอยู่ที่ Client จึงไม่ authoritative (ข้อจำกัดที่ยอมรับตามมติผสม) | OP-01, FR-19, FR-22 |
| 4 | ผู้ใช้เลือกใบเสร็จหลายรายการปนในชุดเดียว | แสดงคำเตือน "ครั้งละ 1 รายการ" ก่อนเลือกไฟล์ ไม่มีกลไกตรวจอัตโนมัติ | FR-22 |
| 5 | แนบไฟล์แต่ยังไม่เชื่อมต่อที่เก็บไฟล์ หรือสิทธิ์หมดอายุ | ที่ขั้นส่งตรวจ ปฏิเสธการส่งพร้อมคำเตือนให้เชื่อมต่อ ไม่ล้มเหลวเงียบ | OP-29, OP-04 |
| 6 | AI/OCR ไม่พร้อมหรือล้มเหลว | ถอยกลับเป็นกรอกเอง/ข้อมูลสาธิตพร้อมแจ้งเส้นทางที่ใช้ ไม่ขวาง flow | OP-02 |
| 7 | PDF แปลงหน้าแรกเป็นภาพไม่ได้ | แจ้งผู้ใช้และให้กรอกเอง | OP-02 |
| 8 | ไม่แนบไฟล์จริง (โหมดสาธิต) | บันทึกใบเสร็จได้ ไม่มี `ReceiptFile` (ข้อยกเว้นของ db-spec กฎข้อ 9) | db-spec กฎข้อ 9 |
| 9 | OP-38 ล้มเหลวหลัง OP-04 บันทึกใบเสร็จแล้ว | **ตัดสินแล้ว (Q-2, ตรงกับระบบที่สร้างแล้ว):** ใบเสร็จถูกบันทึกก่อน (OP-04) แล้วจึงอัปโหลดไฟล์ ถ้าอัปโหลดล้มเหลวใบเสร็จคงอยู่โดยไม่มีไฟล์ (บางไฟล์) ผู้ใช้เห็น error ออกแบบให้ **ไม่ rollback** และให้ผู้ใช้ลองอัปโหลดซ้ำ (OP-38) | OP-38 |

## 6. ประเด็นเปิด

ไม่มี — Q-2 ตัดสินแล้ว (Edge Case ข้อ 9): คงใบเสร็จ ไม่ rollback ให้ลองอัปโหลดซ้ำด้วย OP-38 กับ `Receipt` เดิม
