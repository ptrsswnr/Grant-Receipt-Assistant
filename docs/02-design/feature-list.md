# Feature List — Grant Receipt Assistant

จัดกลุ่ม Functional/Non-Functional Requirements จาก [[backlog]] (อ้างอิงต้นทางที่
[[20260816-01-grant-receipt-verification]]) เป็น "ฟีเจอร์" ที่มีความหมายต่อผู้ใช้งานจริง
สำหรับทีมออกแบบ/พัฒนาอ่านต่อได้ทันที ระบบมี 2 บทบาทผู้ใช้เท่านั้น: **นักวิจัย/เจ้าของทุน**
(ผู้ใช้หลัก) และ **Admin (ผู้ดูแลระบบ/ผู้อัปเดตระเบียบ)** (ดู [[20260816-01-grant-receipt-verification#3. บทบาทผู้ใช้ (User Roles)]])

ระดับความสำคัญ MoSCoW แต่ละฟีเจอร์ map ตรงจากระดับความสำคัญของ backlog เสมอ: **สูง → Must
have, กลาง → Should have, ต่ำ → Could have** (ปัจจุบัน backlog ยังไม่มีรายการระดับ "ต่ำ" เลย
จึงยังไม่มีฟีเจอร์ใดเป็น Could have หรือ Won't have ในรอบนี้)

## 1. อัปโหลดใบเสร็จและอ่านข้อมูลอัตโนมัติด้วย OCR

คำอธิบาย: นักวิจัยอัปโหลดไฟล์ภาพถ่าย (jpg/png) หรือไฟล์ PDF สแกนของใบเสร็จ ผูกกับทุนวิจัยของ
ตนเอง จากนั้นระบบอ่านข้อมูลสำคัญจากใบเสร็จภาษาไทยอัตโนมัติ ได้แก่ ยอดเงิน วันที่ หมวดค่าใช้จ่าย
และชื่อร้าน/ผู้ขาย (ถ้ามี) เพื่อลดภาระการกรอกข้อมูลเองและใช้เป็น input เข้า Rule Engine ต่อไป

รหัส FR/NFR:
- [[20260816-01-grant-receipt-verification#4. Functional Requirements|FR-01]] — อัปโหลดใบเสร็จ
- [[20260816-01-grant-receipt-verification#4. Functional Requirements|FR-02]] — OCR อ่านข้อมูลใบเสร็จอัตโนมัติ
- [[20260816-01-grant-receipt-verification#5. Non-Functional Requirements|NFR-01]] — OCR ต้องรองรับภาษาไทยเต็มรูปแบบ
- [[20260816-01-grant-receipt-verification#5. Non-Functional Requirements|NFR-06]] — เวลาในการประมวลผล OCR (เป้าหมายตัวเลขยังไม่กำหนด)
- [[20260816-01-grant-receipt-verification#5. Non-Functional Requirements|NFR-07]] — ปริมาณใบเสร็จที่ระบบต้องรองรับ (เป้าหมายตัวเลขยังไม่กำหนด)

บทบาทผู้ใช้: นักวิจัย/เจ้าของทุน
ระดับความสำคัญ (MoSCoW): Must have

## 2. ตรวจสอบและแก้ไขข้อมูลก่อนส่งตรวจ

คำอธิบาย: ก่อนกดส่งข้อมูลเข้า Rule Engine นักวิจัยตรวจทานและแก้ไขข้อมูลที่ OCR อ่านได้ (ยอดเงิน
วันที่ หมวดค่าใช้จ่าย ชื่อร้าน) เพื่อป้องกันผลตรวจผิดพลาดจากกรณี OCR อ่านตัวเลข/ข้อความผิด ซึ่งจะ
ทำให้ผลตรวจจาก Rule Engine ในขั้นถัดไปคลาดเคลื่อนไปด้วย

รหัส FR/NFR:
- [[20260816-01-grant-receipt-verification#4. Functional Requirements|FR-03]] — ตรวจสอบ/แก้ไขข้อมูลจาก OCR ก่อนส่งตรวจ

บทบาทผู้ใช้: นักวิจัย/เจ้าของทุน
ระดับความสำคัญ (MoSCoW): Must have

## 3. ตรวจสอบใบเสร็จด้วย Rule Engine พร้อมคำอธิบายจาก LLM

คำอธิบาย: ระบบตรวจใบเสร็จเทียบกับระเบียบทุนวิจัยของมหาวิทยาลัยที่ถูก encode ไว้ใน Rule-based
Engine (เช่น หมวดค่าใช้จ่ายที่อนุญาต วงเงินสูงสุดต่อหมวด เอกสารประกอบที่ต้องมี) — **Rule Engine
เป็นผู้ตัดสินใจ ไม่ใช่ LLM** จากนั้น LLM ทำหน้าที่แปลผลลัพธ์เป็นภาษาไทยที่คนไม่มีพื้นฐานการเงินเข้าใจ
ง่าย พร้อมคำแนะนำแก้ไขที่เป็นรูปธรรม และระบบแสดงสถานะใบเสร็จแต่ละใบ (ผ่าน / ต้องแก้ไข / ไม่เข้า
เงื่อนไข) พร้อมอ้างอิงข้อระเบียบที่ใช้ตัดสิน เพื่อความโปร่งใสและรองรับการโต้แย้ง (dispute) การ
ออกแบบนี้ตั้งใจกัน hallucination จาก LLM โดยตรง

รหัส FR/NFR:
- [[20260816-01-grant-receipt-verification#4. Functional Requirements|FR-04]] — ตรวจใบเสร็จด้วย Rule-based Engine
- [[20260816-01-grant-receipt-verification#4. Functional Requirements|FR-05]] — LLM สรุปผลตรวจเป็นภาษาที่เข้าใจง่าย
- [[20260816-01-grant-receipt-verification#4. Functional Requirements|FR-06]] — แสดงสถานะใบเสร็จรายใบพร้อมเหตุผลอ้างอิงระเบียบ
- [[20260816-01-grant-receipt-verification#5. Non-Functional Requirements|NFR-01]] — คำอธิบายจาก LLM ต้องเป็นภาษาไทย
- [[20260816-01-grant-receipt-verification#5. Non-Functional Requirements|NFR-02]] — ภาษาที่ใช้ต้องเข้าใจง่ายสำหรับคนไม่มีพื้นฐานการเงิน
- [[20260816-01-grant-receipt-verification#5. Non-Functional Requirements|NFR-03]] — Explainability: ผลตรวจต้องอ้างอิงข้อระเบียบได้เสมอ
- [[20260816-01-grant-receipt-verification#5. Non-Functional Requirements|NFR-04]] — Audit Trail: บันทึกกฎ/เวอร์ชันระเบียบ/ผลลัพธ์ต่อใบเสร็จ
- [[20260816-01-grant-receipt-verification#5. Non-Functional Requirements|NFR-06]] — เวลาในการตรวจ Rule Engine (เป้าหมายตัวเลขยังไม่กำหนด)

บทบาทผู้ใช้: นักวิจัย/เจ้าของทุน
ระดับความสำคัญ (MoSCoW): Must have

## 4. แก้ไขและส่งใบเสร็จที่ไม่ผ่านตรวจซ้ำ

คำอธิบาย: เมื่อใบเสร็จมีสถานะ "ต้องแก้ไข" หรือ "ไม่เข้าเงื่อนไข" นักวิจัยแก้ไขข้อมูลหรืออัปโหลดใบเสร็จ
ใหม่แทนใบเดิม แล้วส่งเข้า Rule Engine ตรวจซ้ำ (วนกลับไปยังฟีเจอร์ที่ 3) จนกว่าใบเสร็จจะผ่านการตรวจ

รหัส FR/NFR:
- [[20260816-01-grant-receipt-verification#4. Functional Requirements|FR-07]] — แก้ไขและอัปโหลดใบเสร็จซ้ำ

บทบาทผู้ใช้: นักวิจัย/เจ้าของทุน
ระดับความสำคัญ (MoSCoW): Must have

## 5. Dashboard สรุปภาพรวมใบเสร็จของทุน

คำอธิบาย: นักวิจัยดูภาพรวมสถานะใบเสร็จทั้งหมดของทุนแต่ละก้อนที่ตนเองถือ (จำนวนที่ผ่าน/ต้องแก้/
ไม่เข้าเงื่อนไข) เพื่อติดตามความคืบหน้าการเตรียมเอกสารก่อนยื่นเบิกจริงกับเจ้าหน้าที่การเงิน

รหัส FR/NFR:
- [[20260816-01-grant-receipt-verification#4. Functional Requirements|FR-08]] — หน้าสรุปภาพรวมใบเสร็จของทุน (Dashboard)

บทบาทผู้ใช้: นักวิจัย/เจ้าของทุน
ระดับความสำคัญ (MoSCoW): Should have

## 6. แจ้งเตือนใบเสร็จที่มีปัญหาค้างอยู่

คำอธิบาย: ระบบแจ้งเตือนนักวิจัยเมื่อมีใบเสร็จสถานะ "ต้องแก้ไข"/"ไม่เข้าเงื่อนไข" ค้างอยู่ยังไม่ได้รับ
การแก้ไข เพื่อกระตุ้นให้แก้ก่อนสาย (ไม่รวมการแจ้งเตือนตามกำหนดเวลาส่งหลักฐานรายทุน ซึ่งถูกตัดออก
จากขอบเขต MVP นี้แล้ว — ดู [[20260816-01-grant-receipt-verification#2.2 ตัดออกจากขอบเขต MVP นี้ (ยืนยันโดยผู้ใช้เมื่อ 2026-08-16 — ดูหัวข้อ 7)]])

รหัส FR/NFR:
- [[20260816-01-grant-receipt-verification#4. Functional Requirements|FR-09]] — แจ้งเตือนใบเสร็จที่มีปัญหายังไม่แก้ไข

บทบาทผู้ใช้: นักวิจัย/เจ้าของทุน
ระดับความสำคัญ (MoSCoW): Should have

## 7. Export รายงานสรุปใบเสร็จที่ผ่านตรวจแล้ว

คำอธิบาย: ระบบสร้าง/export ไฟล์รายงานสรุปใบเสร็จที่ผ่านการตรวจแล้วของทุน สำหรับให้นักวิจัยนำไป
ยื่นต่อเจ้าหน้าที่การเงินของมหาวิทยาลัยเอง เจ้าหน้าที่การเงิน**ไม่ใช่ user ของระบบนี้** เป็นเพียงผู้รับ
ไฟล์ที่ export ออกไปภายนอกระบบเท่านั้น (ตัดบทบาทนี้ออกจากระบบทั้งหมดแล้ว ยืนยันโดยผู้ใช้)

รหัส FR/NFR:
- [[20260816-01-grant-receipt-verification#4. Functional Requirements|FR-10]] — Export รายงานสรุปใบเสร็จที่ผ่านตรวจแล้ว

บทบาทผู้ใช้: นักวิจัย/เจ้าของทุน
ระดับความสำคัญ (MoSCoW): Must have

## 8. นำเข้า/อัปเดตระเบียบทุนวิจัยเข้าสู่ Rule Engine (Admin)

คำอธิบาย: Admin นำเข้าและอัปเดตกฎ/เงื่อนไขจากระเบียบทุนวิจัยของมหาวิทยาลัยเข้าสู่ Rule Engine
เมื่อระเบียบมีการเปลี่ยนแปลง โดยไม่ต้อง retrain LLM ระบบบันทึกเวอร์ชันระเบียบที่ใช้ไว้เพื่อรองรับการ
ตรวจสอบย้อนหลังเมื่อระเบียบเปลี่ยนแปลงตามเวลา

รหัส FR/NFR:
- [[20260816-01-grant-receipt-verification#4. Functional Requirements|FR-11]] — นำเข้า/อัปเดตระเบียบทุนวิจัยเข้าสู่ Rule Engine
- [[20260816-01-grant-receipt-verification#5. Non-Functional Requirements|NFR-04]] — Audit Trail: บันทึกเวอร์ชันระเบียบที่ใช้ตรวจ

บทบาทผู้ใช้: Admin (ผู้ดูแลระบบ/ผู้อัปเดตระเบียบ)
ระดับความสำคัญ (MoSCoW): Must have

## 9. จำกัดสิทธิ์การเข้าถึงข้อมูลตามเจ้าของ (Access Control)

คำอธิบาย: นักวิจัยเห็นและเข้าถึงได้เฉพาะใบเสร็จและทุนของตนเองเท่านั้น ส่วน Admin ไม่มีสิทธิ์เข้าถึง
ข้อมูลใบเสร็จส่วนบุคคลของนักวิจัยเลย จำกัดขอบเขตเฉพาะการจัดการระเบียบ/กฎใน Rule Engine — ไม่มี
บทบาทอื่นใดในระบบที่เห็นข้อมูลใบเสร็จข้ามคนได้ ฟีเจอร์นี้เป็นข้อจำกัดที่ครอบคลุมทุกฟีเจอร์ข้างต้น
(cross-cutting) ไม่ใช่หน้าจอเฉพาะของตัวเอง

รหัส FR/NFR:
- [[20260816-01-grant-receipt-verification#4. Functional Requirements|FR-12]] — จำกัดสิทธิ์การเข้าถึงข้อมูลใบเสร็จตามเจ้าของ
- [[20260816-01-grant-receipt-verification#5. Non-Functional Requirements|NFR-05]] — Security/Access Control

บทบาทผู้ใช้: นักวิจัย/เจ้าของทุน, Admin (ผู้ดูแลระบบ/ผู้อัปเดตระเบียบ)
ระดับความสำคัญ (MoSCoW): Must have
