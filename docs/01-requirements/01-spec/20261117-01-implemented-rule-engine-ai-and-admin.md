# Grant Receipt Assistant — ความต้องการของฟีเจอร์ที่สร้างเสร็จแล้ว (2026-09-10 ถึง 2026-11-17)

> เอกสารนี้**บันทึกสิ่งที่สร้างจริงแล้วในระบบ** ไม่ใช่การขอฟีเจอร์ใหม่ เพื่อให้ spec ตามทันโค้ดที่ใช้งานอยู่
> ต่อยอดจาก [[20260816-01-grant-receipt-verification]] (FR-01–FR-12, FR-19, FR-21–FR-23, NFR-01–NFR-07)
> และ [[20260816-02-pdpa-compliance]] (NFR-08–NFR-11) รหัสใหม่เริ่มที่ **FR-24** และ **NFR-12**
> ส่วนรายละเอียดทางเทคนิคของแต่ละข้ออยู่ใน `CLAUDE.md` ที่ root ของโปรเจกต์
>
> **ข้อกำหนด/ข้อจำกัดที่ทราบแล้ว** (ดูหัวข้อ 5): proxy ยังไม่ได้ deploy, หลักฐานเอกสารแนบนักวิจัยติ๊กยืนยันเอง,
> ใบสรุปรายรับ-จ่ายตรวจรายใบเท่านั้น, ชุดประเมินผลยังไม่มีข้อมูลจริง, คีย์ OpenRouter เป็นของคลาสเท่านั้น

## 1. บทนำและขอบเขต

เอกสารนี้ขยายความต้องการหลักเดิมใน 3 ด้าน
1. **ตัวตัดสิน**: Rule Engine เป็นโมดูลบริสุทธิ์ ตรวจ 4 ด้าน (ประมาณการ, ระเบียบ, ใบสรุปรายรับ-จ่าย, เอกสารแนบ) — ต่อยอด FR-04/FR-06
2. **การอ่านและอธิบาย**: AI/OCR อ่านใบเสร็จ และ AI agent อธิบายผลตามกฎในระบบเท่านั้น — ต่อยอด FR-02/FR-05
3. **การบริหาร/วิจัย**: Admin Dashboard, การแนบไฟล์, proxy, ชุดประเมินผลวิทยานิพนธ์ และ NFR การเข้าถึง

หลักการที่ยังคงเดิมตาม [[20260816-01-grant-receipt-verification#1. ภาพรวม/วัตถุประสงค์ของระบบ]]:
**กฎตัดสินเสมอ AI ไม่ตัดสิน** (กัน hallucination)

## 2. Functional Requirements

| รหัส | ความต้องการ | รายละเอียด | ระดับความสำคัญ |
|------|-------------|------------|----------------|
| FR-24 | Rule Engine เป็นโมดูลบริสุทธิ์ มีเวอร์ชัน ตรวจย้อนได้ | ต่อยอด FR-04/NFR-04 — ตรรกะตัดสินแยกเป็นฟังก์ชันบริสุทธิ์ (`RuleEngine.evaluate`) ไม่ผูกกับฐานข้อมูล/หน้าจอ/เครือข่าย ใช้ซ้ำได้ทั้งในเบราว์เซอร์และชุดทดสอบ/ประเมินผลนอกระบบ ทุกผลตรวจต้องมี `reasonCode` (รหัสเหตุผลแบบ machine-readable), `engineVersion`, `autoVerified` (ตรวจจริงหรือแค่ผ่านตามหมวดโดยไม่ได้ตรวจตัวเลข), `citation` (ข้อระเบียบที่อ้าง) และบันทึกใน `receipt.ruleCheck` พร้อม `ruleItemId`/`ruleVersionId`/`fundSourceId`/`findings` เพื่อย้อนกลับไปยังกฎและเวอร์ชันเครื่องมือที่ตัดสินได้ ต้องเพิ่มเลขเวอร์ชันของ engine ทุกครั้งที่ตรรกะตัดสินเปลี่ยน กฎตัดสินเสมอ AI แค่อ่านใบเสร็จและอธิบาย | สูง |
| FR-25 | ผลตรวจ 4 ระดับ และลำดับการตรวจ | ต่อยอด FR-06 — ผลตรวจมี 4 ระดับเรียงจากเบาไปหนัก: **ผ่าน / ต้องแก้ไข / ต้องชี้แจง/ขออนุมัติ / ไม่เข้าเงื่อนไข** (เพิ่ม "ต้องชี้แจง/ขออนุมัติ" จาก 3 ระดับเดิม) สถานะของใบเสร็จคือข้อค้นพบที่รุนแรงที่สุด ระบบตรวจตามลำดับ **ประมาณการ → ระเบียบ → ใบสรุปรายรับ-จ่าย → เอกสารแนบ** และแสดงข้อค้นพบทั้งหมดรายกลุ่ม (`findings[]`) ไม่ใช่แค่ข้อแรกที่พบ สถานะแสดงด้วยสี+ไอคอน+ข้อความเสมอ (ดู NFR-13) | สูง |
| FR-26 | ตรวจกับประมาณการที่อนุมัติ (ตาราง 17.2) | นักวิจัยนำเข้าไฟล์ตารางประมาณการ 17.2 ของมหาวิทยาลัย (.xlsx/.csv) ต่อโครงการ ระบบแปลงเป็นรายการประมาณการและจับคู่หมวดระเบียบให้ (แก้ไขเองได้ก่อนบันทึก) การตรวจ: (1) ไม่อยู่ในประมาณการ หรือ (2) ยอดสะสมของรายการเกิน **100%** ของยอดรวมทั้งโครงการของรายการนั้น → **ต้องชี้แจง/ขออนุมัติ** (3) ระบบอ่านจำนวนหน่วยจากช่องตัวคูณ (ชั่วโมง, กม., คน×มื้อ) แล้วตรวจ **อัตรา × จำนวน** เทียบเพดานตามระเบียบ และเตือนตอนนำเข้าหากหน่วยราคา×จำนวนไม่เท่ายอดรวม (4) มีหน้าแสดง **ยอดใช้ไป / คงเหลือ / % ต่อรายการ** ของแต่ละโครงการ (5) หากรายการประมาณการไม่มีจำนวนหน่วยหรือยังไม่มีประมาณการ ผลตรวจต้องบอกให้นักวิจัยอัปโหลด/อัปโหลดประมาณการใหม่ แทนการปล่อยผ่านเงียบๆ | สูง |
| FR-27 | ตรวจความครบของเอกสารแนบตามชุดเอกสาร (Evidence Chain) | ต่อยอด FR-04 ("เอกสารประกอบที่ต้องมี") — แต่ละหมวดค่าใช้จ่ายผูกกับชุดเอกสาร (evidence chain) ระบบแสดงรายการตรวจสอบให้นักวิจัยติ๊กว่ามีเอกสารใดแล้ว และตรวจว่าครบ ครอบคลุม: ตรา **"จ่ายแล้ว"**, ตรา**ตรวจรับพัสดุ**, **รูปถ่ายพัสดุ**, **หนังสืออนุมัติก่อนดำเนินการ** (ค่าตอบแทน/เดินทาง/จ้างตาม TOR/ครุภัณฑ์), และ**กรรมการตรวจรับ 3 คนเมื่อยอดเกิน 100,000 บาท** (การเงินยืนยันเมื่อ 2026-11-17) ขั้นที่รับเอกสารทางเลือกได้ตามที่ระเบียบกำหนด (เช่น ค่าที่พักเหมาจ่ายใช้ **วจ.2 อย่างเดียวได้** — การเงินยืนยัน) ขั้นที่ไม่บังคับต้องไม่ทำให้ไม่ผ่าน เอกสาร/ตราที่ขาดทำให้ผลเป็น **ต้องแก้ไข** | สูง |
| FR-28 | เทียบยอดกับใบสรุปรายรับ-จ่าย | นักวิจัยกรอกยอดที่ลงไว้ในใบสรุปรายรับ-จ่ายโครงการ (ไม่บังคับ) ระบบเทียบกับยอดใบเสร็จ หากไม่ตรง → **ต้องแก้ไข** ตรงกัน → ผ่านข้อนี้ ไม่กรอก → ไม่มีข้อค้นพบ | กลาง |
| FR-29 | ชุดกฎตามคู่มือจริง (rule set 2570.4) | ต่อยอด FR-11 — กฎของแหล่งทุนใช้ตัวเลขและเงื่อนไขจาก "คู่มือฯ ปีงบประมาณ 2570" และ "คู่มือการกรอกแบบฟอร์มและตัวอย่างใบเสร็จ ฉบับปรับปรุง" ครอบคลุม **28 หมวดรายการ** แต่ละกฎอ้างอิงแหล่งที่มา (ข้อ/หน้า) ในหมายเหตุ ประเภทอัตรามี เพดานตามจริง / เหมาจ่าย / ต่อหน่วย / ตามข้อเสนอโครงการ รายการที่คู่มือไม่ระบุตัวเลขตายตัวต้องไม่ถูกแต่งตัวเลขขึ้นเอง หมวดที่คู่มือไม่สนับสนุน (เช่น ค่าตอบแทนคณะผู้วิจัย) ต้องได้ผล "ไม่เข้าเงื่อนไข" ชุดกฎปัจจุบันคือ **2570.4** (บันทึกข้อยืนยันจากการเงิน) กฎที่แก้ในไฟล์ตั้งต้นต้องผลักเข้าฐานข้อมูลจริงผ่านปุ่มอัปเดตระเบียบโดย Admin | สูง |
| FR-30 | อ่านใบเสร็จด้วย AI และ OCR ภาษาไทยในเครื่อง | ต่อยอด FR-02/FR-03 — (1) AI อ่านภาพ/PDF หน้าแรกของใบเสร็จแล้วเสนอ ยอด/วันที่/หมวด/ชื่อร้าน พร้อมป้าย "AI suggestion" เฉพาะเมื่อ AI ทำงานจริง (2) ผู้ให้บริการ AI สลับได้ผ่านการตั้งค่า: OpenRouter / Ollama ในเครื่อง / proxy / custom (3) OCR ภาษาไทยในเครื่อง (OpenThai 2.0) ใบเสร็จไม่ออกจากเครื่อง — ใช้ส่งบรรทัดข้อความเข้า AI ประกอบภาพ หรือสกัดยอด/วันที่ (พ.ศ.→ค.ศ.)/ชื่อร้านเองเมื่อไม่มี AI (4) ไม่มี AI/OCR หรือเรียกล้มเหลว ต้องถอยกลับเป็นกรอกเองหรือข้อมูลสาธิต พร้อมแจ้งว่าใช้เส้นทางใด (5) นักวิจัยตรวจ/แก้ไขทุกค่าก่อนส่ง (FR-03) | สูง |
| FR-31 | AI agent อธิบายผลจากกฎในระบบเท่านั้น และบันทึก agentLogs | ต่อยอด FR-05 — agent ดึงชุดเอกสาร/ประเภทเอกสารที่เกี่ยวข้องจากระบบ แล้วให้ AI สรุปผลเป็นภาษาไทยพร้อมวิธีแก้ ข้อห้าม: ห้ามใช้ความรู้ภายนอก ห้ามแต่งกฎ/เอกสารขึ้นเอง ห้ามอ้างว่าเห็นหรือตรวจไฟล์ที่แนบ **agent ไม่เปลี่ยนสถานะผลตรวจ** ทุกครั้งที่รัน (ใช้ AI หรือถอยกลับก็ตาม) ต้องบันทึกประวัติลงใน `agentLogs` ของใบเสร็จ (ใช้ AI หรือไม่, โมเดล, ชุดเอกสาร, คำอธิบายสุดท้าย, ระยะเวลา) ความล้มเหลวของ agent ต้องไม่ขัดขวางการบันทึกใบเสร็จ | สูง |
| FR-32 | แนบไฟล์จริงผ่าน Google Drive ของผู้ใช้ | ต่อยอด FR-01/FR-22 — แทน Firebase Storage นักวิจัยกดเชื่อมต่อ Google Drive ของตนเอง (สิทธิ์ `drive.file` เท่านั้น) ไฟล์เก็บในโฟลเดอร์แยกตามรหัสใบเสร็จ และตั้งเป็น "ผู้ที่มีลิงก์ดูได้" เพื่อแสดงเป็นลิงก์ในหน้ารายการ/Admin หากแนบไฟล์แต่ยังไม่ได้เชื่อมต่อ (หรือโทเค็นหมดอายุ) ต้องเตือนแทนการล้มเหลวเงียบ การลบใบเสร็จยังไม่ลบไฟล์ใน Drive | กลาง |
| FR-33 | Admin อ่านใบเสร็จทุกคนแบบอ่านอย่างเดียว และจัดการกฎ/แหล่งทุน | กลับคำตัดสินใจเดิมของ FR-12/NFR-05 (2026-09-10) — Admin เห็นรายละเอียดใบเสร็จของทุกคน (ระบุเจ้าของ) ผ่าน Admin Dashboard พร้อมสรุปตามสถานะ/หมวด/แหล่งทุน อ่านได้อย่างเดียว เขียน/แก้ใบเสร็จของผู้อื่นไม่ได้ และผู้ใช้ทั่วไปไม่เห็นเมนู Admin Admin จัดการแหล่งทุน (เพิ่ม/ลบ) และกฎรายหมวดได้ ต้องแจ้งนักวิจัยก่อนอัปโหลดครั้งแรกว่า Admin อ่านข้อมูลได้ (ผ่านการยินยอมแบบเบา ดู FR-13/FR-14) การเลื่อนสิทธิ์เป็น Admin ทำผ่านคอนโซลเท่านั้น ไม่มี UI ให้ยกสิทธิ์ตนเอง | สูง |
| FR-34 | ชุดประเมินผลสำหรับวิทยานิพนธ์ | เครื่องมือรันนอกระบบที่เทียบผลของระบบกับผลที่เจ้าหน้าที่การเงินตัดสินจากไฟล์เคส (CSV) รายงาน **accuracy, Cohen's kappa, macro F1, จำนวนปัญหาที่ระบบพลาด (missed), จำนวนแจ้งเตือนเกิน (false alarm)** และเทียบกับ **AI ตัดสินเองล้วน (baseline)** ที่ได้กฎชุดเดียวกันเป็นข้อความ ผลลัพธ์เขียนเป็นไฟล์รายงาน ข้อมูลจริงห้ามเข้า git | กลาง |

## 3. Non-Functional Requirements

| รหัส | ด้าน | ความต้องการ |
|------|------|-------------|
| NFR-12 | Security — AI Proxy | พร็อกซีถือ API key ของผู้ให้บริการ AI ไว้ฝั่งเซิร์ฟเวอร์ รับคำขอเฉพาะผู้ใช้ที่ล็อกอิน (ตรวจลายเซ็น/ผู้รับ/ผู้ออก/วันหมดอายุของ Firebase ID token) จำกัดเว็บต้นทางและโมเดลที่อนุญาต เพื่อไม่ให้คีย์ปรากฏฝั่งเบราว์เซอร์ **สถานะ: เขียนโค้ดและทดสอบแล้ว ยังไม่ได้ deploy** เกี่ยวข้อง NFR-08 |
| NFR-13 | Accessibility | รองรับผู้ใช้สูงอายุ: ตัวอักษรเนื้อหา ≥ 16px และข้อความ UI ≥ 14px, ช่องกรอก/ปุ่มสูงอย่างน้อย 44px, โหมดกลางคืน (สว่าง/มืด/ตามระบบ; ค่าเริ่มต้นสว่าง) และเลือกสีเน้นได้ โดยสีเน้นต้องไม่สับสนกับสีสถานะผลตรวจ, **สถานะไม่พึ่งสีอย่างเดียว** (มีไอคอนและข้อความกำกับเสมอ), ลำดับหัวข้อไม่ข้ามระดับ, ใช้งานบนมือถือได้ |
| NFR-14 | Privacy — ประมวลผลในเครื่อง | ต้องมีทางเลือกอ่านใบเสร็จโดยไม่ส่งภาพออกนอกเครื่อง (OCR ในเครื่อง + AI ในเครื่อง) เพื่อรองรับข้อกังวลเรื่องข้อมูลส่วนบุคคลและการส่งข้อมูลข้ามประเทศ (ดู NFR-08) การใช้ผู้ให้บริการภายนอกเป็นการตัดสินใจเป็นรายกรณี |

## 5. ข้อจำกัดที่ทราบอยู่แล้ว (ไม่ต้องถามซ้ำ)

- **Proxy (NFR-12)**: ยังไม่ได้ deploy
- **เอกสารแนบ (FR-27)**: นักวิจัยติ๊กยืนยันเอง ยังไม่ได้ตรวจจากไฟล์จริง (ออกแบบให้การจำแนกเอกสารด้วย OCR มาเติมค่าได้ภายหลังโดยไม่แก้ engine)
- **ใบสรุปรายรับ-จ่าย (FR-28)**: ตรวจรายใบเท่านั้น ยังไม่ตรวจยอดรวมรายหมวดของทั้งชุด
- **ชุดประเมินผล (FR-34)**: ยังไม่มีข้อมูลจริง (รอ EC) มีแค่เคสสมมติ และยังไม่ได้รัน baseline กับ API ที่เสียเงิน
- **คีย์ OpenRouter (FR-30)**: เป็นของคลาส ใช้ได้เฉพาะวิชาเรียน งานวิจัยต้องใช้ Ollama หรือคีย์ของตนเอง
- **ค่าที่พักเหมาจ่าย 800 บาท/วัน**: ใช้วจ.2 ได้ตามที่การเงินยืนยัน (FR-27)
