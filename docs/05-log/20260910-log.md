# Log — 2026-09-10

## Admin Dashboard + Rule Editor + Fund Source CRUD — reverses FR-12/NFR-05's admin restriction

**บริบท**: ผู้ใช้ขอฟีเจอร์ 3 อย่าง: (1) Admin Dashboard ที่ admin เห็นได้ว่าแต่ละ user อัปโหลด
ใบเสร็จอะไรบ้าง สำหรับใช้เป็นข้อมูลรายงานผู้บริหารและแนวทางปรับปรุงระบบ, (2) admin แก้ไขกฎใบเสร็จ
(ruleItems) ของแต่ละแหล่งทุนได้ และเพิ่ม/ลบแหล่งทุนได้, (3) นักวิจัยยังคงเลือกแหล่งทุนจาก dropdown
ตอนสร้างโครงการ และเห็นเฉพาะข้อมูลของตัวเอง (ข้อ 3 มีอยู่แล้วก่อนหน้านี้ ไม่ต้องแก้)

ก่อนเริ่มงาน ตรวจสอบพบว่าข้อ (1) ขัดกับการตัดสินใจที่ยืนยันแล้วในสเปคหลัก
([[20260816-01-grant-receipt-verification]]) — **FR-12, NFR-05, และหัวข้อ 8 ข้อ 4** (ยืนยันเมื่อ
2026-08-16) ระบุชัดเจนว่า "Admin ไม่มีสิทธิ์เข้าถึงข้อมูลใบเสร็จส่วนบุคคลของนักวิจัย" — ไม่ใช่ช่องโหว่
ที่ลืมทำ แต่เป็นการตัดสินใจเรื่อง privacy โดยตั้งใจ (prototype เดิม `admin-rule-management.html`
ก็เขียนกำกับไว้ตรงกัน) จึงหยุดถามผู้ใช้ก่อนดำเนินการต่อ (ผ่าน `AskUserQuestion`) — ผู้ใช้ยืนยันชัดเจนว่า
**ต้องการกลับคำตัดสินใจเดิม**: ให้ admin เห็นรายละเอียดใบเสร็จของทุก user ได้เต็มรูปแบบ (ระบุตัวตน
เจ้าของ ไม่ anonymize)

**ข้อมูลอ้างอิงที่ใช้ออกแบบ Rule Editor**: ผู้ใช้แชร์โฟลเดอร์ Google Drive ที่มีคู่มือจริงของมหาวิทยาลัย
แม่ฟ้าหลวง — อ่าน "คู่มือบริหารจัดการโครงการวิจัยมหาวิทยาลัยแม่ฟ้าหลวง (ฉบับนักวิจัย) 2566" (76 หน้า, มี
text layer จริง ไม่ใช่สแกน) พบว่าระเบียบจริงซับซ้อนกว่าโครงสร้าง `ruleItems` เดิม (หมวด + วงเงินสูงสุด
ตัวเดียว) มาก — มีทั้งอัตราต่อหน่วย (3.5 บาท/กม.), เหมาจ่ายต่อหน่วย (700 บาท/คน/ครั้ง TAXI, 400
บาท/คน/คืน พักบ้านญาติ), เพดานตามจริง (ไม่เกิน 1,600 บาท/วัน ค่าที่พัก), และบางหมวด (ค่าตอบแทน/
ค่าจ้าง) ไม่มีเพดานระดับแหล่งทุนเลย — ใช้ตัวเลขจากข้อเสนอโครงการของโครงการนั้นๆ เอง จึงขยาย field ของ
`ruleItems` เพิ่ม `rateType`/`rateAmount`/`unit`/`requiredEvidenceType`/`note` แทนที่จะมีแค่
`categoryName`/`maxAmount` (ดูรายละเอียดใน `CLAUDE.md`)

**ขอบเขตที่ตัดออกโดยตรงจากผู้ใช้ (ยืนยันแล้ว ไม่ใช่ยังไม่ตัดสินใจ)**:
- การบังคับใช้ (enforce) ว่าต้องแนบเอกสารประเภทใดต่อหมวด — เก็บแค่ field `requiredEvidenceType` ไว้
  อ้างอิง ไม่ตรวจสอบจริง
- การเทียบใบเสร็จกับข้อเสนอโครงการต้นฉบับที่อาจารย์ยื่นไว้ — ไม่ทำรอบนี้

**สถาปัตยกรรมที่ยังไม่มี (ผู้ใช้ทราบแล้ว)**: ยังไม่มี server ของมหาวิทยาลัย (จะขอภายหลัง), ยังไม่มี
OCR/LLM จริง — Rule Engine ยังเป็น mock เหมือนเดิมตาม `SCOPE.md` แต่เปลี่ยนจาก hardcode เป็นอ่านจาก
`ruleItems` จริงใน Firestore (data-driven mock) แนะนำให้อนาคตใช้แนวทาง RAG (ให้ LLM อ้างอิงเอกสาร
ต้นฉบับที่แนบไว้ตรงๆ ตอนตัดสิน) แทนการพยายาม parse ระเบียบทั้งหมดเป็น structured data ล่วงหน้า
เพราะระเบียบจริงมีเงื่อนไข/ข้อยกเว้นแบบ prose เยอะเกินจะ formalize ได้หมด
